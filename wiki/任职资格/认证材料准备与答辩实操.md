# 认证材料准备与答辩实操

> **状态**：unreviewed
> **最后更新**：2026-09-16
> **来源**：任职资格认证辅导/打磨系列会议 5 篇（见 frontmatter `sources`，均可溯源至 `raw/收件箱/` 语音转写原稿）
> **定位**：[[wiki/任职资格/PMC经理能力模型]] 讲的是**标准是什么**，本页讲的是**怎么把标准变成一份能拿分的材料、并讲对**。

## 核心要点

- **一句话原理**：先把**职责讲透**（上下游、为什么设这个职责、解决什么问题），案例是**长出来的**，不是凑出来的 —— "职责理解透了，其实你什么案例都能套进去"。
- **材料三件套**：① 工作场景清单 ② 每个场景拆到一~四级的能力要求 ③ 能力项样例（原文 → 员工化解读 → 考察点 → 案例指引 → 真实案例）。
- **案例策略**：找 **3–5 个覆盖广的复杂案例**，不要求多；**案例越复杂，打分尺度越高**；正面案例不一定最优，**负面案例也可能最优**。
- **论证顺序**：先讲"我是干什么的" → 再讲等级边界 → 再讲业务链路（画得出来） → 再讲案例 → 最后做映射。
- **映射呈现法（本篇最可复用的一招）**：**26 项要素常驻页面边缘 + 讲到哪页高亮本页覆盖项 + 一条累计进度百分比**。一页同时回答"这页我具备什么能力"和"我总的积累到哪了"。
- **证据必须做成清单并排序**（101/102/103… 每条注明对应什么、放哪里）；底稿 → PPT。
- **二三级边界要讲，但要反着说**："**我超过了一级、达到了二级**"，而不是"我达到了二级、有的达到三级"。
- **职责与要素是"多对多"，不是一一对应** —— 十个职责是岗位工作的全集罗列，26 项要素是再拆到细则，**一对多、多对一都有**。
- ⚠️ **反直觉陷阱**：**写得越细 ≠ 越安全**。写得细，评委会认为你已经掌握得很深、反而没什么好问；**模糊定义更容易被提问，到时候反而不好回答**。
- **胜负手**：**对上级的依赖度** —— 依赖多落在 P3 区间，依赖少落在 P4 区间。

## 详细内容

### 一、材料三件套

| # | 成果物 | 内容 | 备注 |
|:-:|--------|------|------|
| 1 | **工作场景清单** | 十大工作场景 + 场景定义 | 场景定义可用 AI 辅助生成；日常工作事例摘自岗位培训表单里的职责内容；"**只是参考，你有更好的业务场景可以用自己的**" |
| 2 | **分级能力要求** | 每个场景拆到一/二/三/四级 | 目的是"方便看清楚你做这个事项能匹配到几级" |
| 3 | **能力项样例** | 五段式（见下） | 三级样例的结构 |

**能力项样例的五段式结构**

```
① 任职资格原文（素质能力 / 知识技能 / 行为标准）
② 员工化解读（翻译成员工能懂的话）
③ 考察点（推测评委可能考察的维度）—— ⚠️ 只是推测，不是题库
④ 案例指引（背景 / 动作 / 措施 / 结果 / 影响）
⑤ 真实业务案例（一个完整实例）
```

> 📌 关于 ③ 的边界（原文）："这里只是有一个考察点的参考的维度，他可能也没有办法具体到到时候会问哪些问题……只能结合这一项任职资格原文，推测一下面试官可能会考察哪些内容。"

**案例的统一结构**：`背景 → 动作 → 措施 → 结果 → 影响`。先讲完整业务案例，再回头说明它体现了哪几项能力。

### 二、讲述主线

```
① 我是干什么的（职责理解）
     ↓ 用一个产品 / 一条流程串起来讲，不要背
② 等级边界（二级 vs 三级）
     ↓
③ 业务链路（画得出来，评委才看得懂）
     ↓
④ 场景 / 案例（3–5 个覆盖广的复杂案例）
     ↓
⑤ 案例深度拆解 → 每个流程节点映射到具体要素
```

**被点名的六类常见错误**

| # | 错误 | 表现 |
|:-:|------|------|
| 1 | **没讲等级的理解** | 只把要素"念经背一遍"，没有体感 |
| 2 | **没前置说明"我是干嘛的"** | 直接甩表格，跨部门评委根本不知道你的职责范畴 |
| 3 | **表格缺承接关系** | 没讲这张表承接哪几个核心职责、讲它的目的是什么 |
| 4 | **没讲"为什么选这个场景"** | 来龙去脉没交代；术语也要用对方语言（例："不能讲分销，在他们的理解里 to B 就 to B"） |
| 5 | **链路跳来跳去** | 表格逻辑强，在表格里讲东西最容易讲乱 → **建议直接在表格里加一张流程图** |
| 6 | **映射推演方式错** | "我说 A 我没接触过，其他 9 个我都碰过" —— 这么推演等于宣称其他都会，评委只能狂轰滥炸地追问，**反而没法给分** |

**讲职责的正确姿势（示范）**

> 📌 "你职责一定要理解……你不能现场念。你的核心职责是做什么？要说你对这个职位的理解是什么。"

不做"逐条背职责"，而是**拿一条流程讲清楚**：我为谁服务（业务部门）→ 他的目标/现状/差距是什么 → 差距分三类（**动力不足**＝激励/绩效、**人效不够**＝人机边界/AI 应用、**能力不够**＝培训）→ 分别对应组织诊断 / 绩效 / 激励 / 人才盘点 / 任职资格梳理。

> 📌 结论原文："你的很多场景都可以**串联在一起**做这个事情，就是通过一个流程的概念。"

**复杂案例的六步表达法**（可直接套用）

| 步骤 | 内容 |
|:--:|------|
| 1 | 业务里**最复杂的场景**是什么？先讲清来龙去脉 |
| 2 | **部门 / 业务的要求**是什么？ |
| 3 | **你自己职位的要求**是什么？ |
| 4 | 我**怎么做**？拆成一二三四步 |
| 5 | **为什么这么拆**？过程是什么？ |
| 6 | **结果**如何？有没有达到预期？部门认不认可？ |

> 📌 结论原文："**一件复杂事物的拆解能力**，会成为你未来核心表达的东西，这个才是证明你的能力的地方。"

### 三、26 项要素的映射与举证

**为什么需要专门的呈现方案**：26 项要素是评委的评分表，但在业务案例里顺带讲，**映射会混乱** —— 评委只能抓到一两个关键词，"够不够？不太够"。

**方案 A（推荐）：要素常驻 + 本页高亮 + 累计进度**

- 侧面/底部**常驻 26 项清单**；
- 讲到某页 → **高亮本页覆盖的项**；
- 同页再给一条**累计进度**：本页覆盖 N 项 / 累计已覆盖 XX 项 / 总进度百分比。

> 📌 原文："26 个全部干在边上，然后这页高亮……然后总的：这是这一页高亮里的，然后总的目前覆盖多少。"
> 📌 效果：一页同时回答"这页我具备什么能力"和"我总的积累进度到哪了"。

**方案 B：另做一份《PPT 说明书》发给每位评委**，让他们对着看（动机：26 项全放 PPT 上字太小）。

**方案 C：前后加汇总页** —— 每个核心篇幅后紧跟一页映射（**当下巩固**），或全篇结束做一页总整合（**最后巩固**）。最后巩固的缺点是间隔久了印象会弱。

**执行细节**

- **上标小序号**：把"这一段对应哪一项"标成上标小标号，**由 AI 批量标注**（人工处理很麻烦），同时也给自己讲的时候一个提示。
- **证据必须排序**：
  > 📌 "**所有证据都要进行排序**，你是先要有**证据清单**的……比方说有 3 个或 5 个材料，101 到 105，01 对应什么、02 对应什么、03 对应什么，**带着文字说明要放到哪里** —— 那份是你的底稿，底稿再生成你的 PPT。"
- **纸质材料**：需求方明确要求提供"五个案例对应一二三四五 + 案例里对应的要素"的纸质版 —— **本质就是证据清单 + 排序**。
- **附件区**：单独辟一块放佐证材料图标；或用超链接，但**要很清晰告诉大家这里有超链接**，否则会被当成普通文件。评委感兴趣的会点开，"这样就会更饱满"。
- **自评**：在**每一页**做一份自评供评委参考（评委对规则不熟、来不及打分时能直接对照）。自评**只加在三要素（知识技能 / 行为标准 / 数据能力）那一区**，不放"工作职责"页（那页没有评分项）；是**逐条打分**，不是最后统一打分。

**逐条讲法的核心开关：不要被边界锁死**

> 📌 "我在讲职责的时候，拿一二三四我就讲一二三四？**我讲六不行吗？我讲七不行吗？可以。**不要把边界给自己锁死。"

- **溢出即加分**：认证二级不代表只有二级能力。例：看板项对应"能独立使用看板"，但如果"我有能力自己提看板需求、上级把关后提给 IT 实现" → **加分**。
- 每项都能讲出**超出常规的那一步**（问题同频 > 常规同频；超出职责范畴发现异常 = 创造额外价值）。

### 四、二三级边界怎么讲

**为什么必须讲**（评委视角）

> 📌 "因为评委虽然是要认证二级，**如果评委觉得你就只有二级（一级），把你跨到一级去怎么办？**"

**表述方式（关键）**

> 📌 "关键应该说我**超过了一级、但达到了二级**，而不是说我达到了二级、然后有的达到三级。"

**二级的四个核心特征（也是四个通用表达点）**

| # | 特征 | 含义 |
|:-:|------|------|
| 1 | **独立完成** | 常规业务场景、多个业务产品上能独立做事 |
| 2 | **上级指导** | 复杂业务场景需要上级辅导 |
| 3 | **常规场景 / 多场景** | 覆盖多个常规业务产品 |
| 4 | **形成自己的方法论** | 有沉淀、可复用（尚未到能赋能他人） |

**三级边界**：**精通**所有核心业务产品，**已脱离对部门的依赖**，能主导项目。

**三级内容的作用 = 加分项**

> 📌 "每个人可能没有全部达到三级，但**有些项目已经有，那像这都是加分项目**。"

**职责 ↔ 要素的关系**

> 📌 "职责感觉是把这个人所有的工作给你罗列起来，然后那个（26 项）是再给你拆分出来、拆分到每个细则上面去。所以它本质上**没有一一对应的关系，可能有一对多或者多对一**。"

→ 落地做法：这一页**不写细边界**，只写"自己是**主导还是辅助**"，再结合二级的四个能力点。

### 五、答辩与追问应对

**评委怎么判断一级还是二级**：评委不只看材料，会**向部门长侧面了解**"他日常是不是独立做的"。原文："部门长也不会说'这个都是我教着做' —— **有一个诚信担当的价值观在那**。"

**"AI 抄一份案例能不能混过去"的三道防线**

| 关卡 | 评委的应对 |
|------|-----------|
| ① **场景还原** | "评委会问：当时那个是个什么场景，**你要能讲得出来**" |
| ② **换案例复现** | "如果怀疑你，我一定会问：**你还没有另外一个案例？你再做一个说明**，当时是什么情况" |
| ③ **现场识破背诵** | "**评委在现场，你背的话其实别人看得出来**" |

→ 真正的护城河是**职责的底层本质**："你的职责的底层本质，如果你理解很深的话，你肯定会做。"

**长期视角（比认证更狠的裁判）**

> 📌 "我们以后是在**流程**当中工作的……未来就是**市场经济**，所谓市场经济，就是**小伙伴们都愿意拉你一起干活**。"
> 📌 "（水平不行）也没人要你。那这个时候你就会发现，其实你**再认证高也没用** —— 大家都说'那个水平不行，那个订货都订不清楚'，**马上就暴露出来**。"

### 六、流程与规则

| 项 | 内容 |
|------|------|
| **要素数量** | 三级合计 **26 项**（素质能力 + 知识技能 + 行为标准）；**一个案例可覆盖多项**，不必逐条答辩 |
| **讲述时长** | 20–30 分钟；4–5 个案例，每个约 6 分钟 |
| **PPT 页数** | 建议 **10 页起**（案例增加后十几页） |
| **呈现工具** | **PPT 优于表格** —— 映射关系更直观，表格需要很强的底层逻辑才能讲清楚 |
| **知识技能** | **不考试，也走案例形式体现**；但公司曾提出要重定考核方式（笔试 / 选择 / 判断 / 描述 / 答辩），**方案待定** |
| **预认证** | 走一遍流程、**结果不作真实考核结果**，自愿报名，用来摸清现场提问方式 |
| **正式认证** | **会录像**；表现好、可作范本的优秀案例会进公司资料库 |
| **评委** | 由 **EMT** 组成 |
| **重点职位** | 本轮公司重点输出：**运营经理 / 产品经理 / PMC 经理** |
| **证据时间范围** | **近一年**（去年下半年起）一般都可以用 |
| **佐证缺失** | 可请**部门长参与作证** |
| **跨界要求** | 存在争议（与薪资条款写在一起，但标准正文未体现），**待公司层面确认**；已有口径：水单不算跨界 |
| **自我检验法** | **自己录一遍 15 分钟讲述，回听能不能听懂** —— 听不懂就重做 |

### 七、可直接复用的五条经验

1. **职责理解 > 案例搜集** —— 职责讲透，案例自然长出来。
2. **模糊比详细更危险** —— "写得细，评委觉得你掌握深、没什么好问；**反而是模糊的定义更容易被提问，到时候反而不好回答**。"
3. **不要把边界锁死** —— 溢出边界是加分，不是越界。
4. **对上级的依赖度是分数开关** —— 决定落在 P3 还是 P4。
5. **PPT 不在多，逻辑要闭环** —— "核心是你的内容要讲得很通透、逻辑要闭环。"
