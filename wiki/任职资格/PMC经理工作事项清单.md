# PMC 经理工作事项清单

> **状态**：unreviewed
> **最后更新**：2026-09-16
> **来源**：[[raw/知识归档/知识档案/PMC经理工作事项清单.md]]（清洗自收件箱 `PMC经理工作事项.xlsx` 主表「03-行事历清单」）
> **定位**：与 [[wiki/任职资格/PMC经理能力模型]] 互为表里 —— 能力模型讲**标准要求什么**，本页讲**这个岗位每天实际在干什么**。标准层 ↔ 执行层，两张表对着看，差距就是认证要补的证据。

## 核心要点

- **8 个一级模块 × 34 条事项**：产品档案管理（6）/ 采购订单闭环（8）/ 参与日常库存管理（7）/ 参与供方管理（5）/ 参与供方质量管理（3）/ 参与供方成本管理（1）/ 供方合同及票务（3）/ 周例会（1）。
- **两条主线**：① **采购订单闭环**（下单 → 物流 → 交期 → 付款 → 三单相符 → 到货 → 异常中止）；② **库存保交付防滞销**（日监控 → 清库协同 → 大单发货 → 日常缺货处理）。
- **5 条被标为「重点工作」**：系统创建新品档案、发起采购订单、**三单相符**、监控日常库存保交付防滞销、**日常缺货处理** —— 这五条就是岗位考核权重最高的动作。
- **节奏上"不定时"为主**：34 条里明确周期只有 12 条左右（日 1、每天 2、每周二/三 4、周 2、月 3、季 2、年 1），**其余 20 条属"发生了就干"** —— 这正好对应认证里"复杂场景/异常处理"的取材来源。
- **PMC 是供应链内部的接口人**：协同面覆盖供开部 / 仓储管理部 / 财务部 / 质量部 / CBG / 客服部 / 分销部 / 产品市场部 / 供应商 / 物流货代 / 数字化组。
- **系统栈**：**管家**（主系统）、内部系统、阿里 1688、企业微信、钉钉、BI 报表、物流查询网站。
- ⭐ **对认证的直接用法**：这 34 条是**案例素材池** —— 每条都能挂到 26 项要素上；而"三单相符""日常缺货处理""异常中止退款""代发仓/云仓对接"这几条**天然跨部门、有争议、有取舍**，正是手册说的"**越复杂打分尺度越高**"的取材处。

## 详细内容

### 一、八大模块全景

| 模块 | 条数 | 这块到底在干什么 |
|------|:---:|----------------|
| **产品档案管理** | 6 | 新品建档案、定标签类型、建供方档案、代发运费规则、建组合装编码、清库存 SKU 下架停用 —— **数据地基**，档案不准后面全错 |
| **采购订单闭环** | 8 | 下单 → 配件采购 → 物流调度 → 交期跟踪至入库 → 付款取票 → **三单相符** → 到货跟进 → 异常中止退款 |
| **参与日常库存管理** | 7 | 日监控保交付防滞销、清库协同、物流选择、**代发品退换货**、**代发仓/云仓对接**、大单发货、**日常缺货处理** |
| **参与供方管理** | 5 | 产能与交期监控、关系维护、**绩效管理（KPIs）**、诚信廉洁、风险识别 |
| **参与供方质量管理** | 3 | 质量管控与改善督促、质量异常库存退换索赔、日用品质量周例会 |
| **参与供方成本管理** | 1 | 异常耗损成本向供方磋商赔付（等价货物 / 货款扣除返还） |
| **供方合同及票务** | 3 | 合同签订与管理、票据收集、**冲红退票重开** |
| **周例会** | 1 | 交付成功部每周二例会（做 PPT + BI 取数） |

### 二、节奏视图（把 34 条按固定周期重排）

| 节奏 | 事项 |
|------|------|
| **日** | 系统创建新品档案 |
| **每天** | 维护供方关系；督促供方诚信廉洁 |
| **每周二** | 协同质量部管质量；质量异常退换索赔；**交付成功部例会** |
| **每周三** | 日用品质量周例会 |
| **每周一次** | 清库存 SKU 下架及停用 |
| **周** | 确定标签类型；货品物流安排调度 |
| **每月 15 号前** | 发起供方付款、获取票据 |
| **每月 25 日前** | 供方合同签订与管理；收集票据 |
| **每月一次** | **三单相符** |
| **每月 1 号下班前** | 代发品运费数据更新（提交需求申请单给 IT） |
| **季** | 代发品运费数据更新 |
| **年** | **发起采购订单（重点工作）** |
| **不定时/临时** | 其余 20 条 |

> 💡 **LLM 推断**：固定周期的事项多为**事务性闭环**（档案、付款、票据、例会），价值密度高的"重点工作"反而都在**不定时**那一档 —— 说明这个岗位的能力体现不在"按时做完"，而在**异常发生时怎么判断和协同**。这与 [[wiki/任职资格/认证材料准备与答辩实操]] 的"复杂案例决定打分尺度"是一条逻辑。

### 三、五条「重点工作」详解

| 事项 | 为什么是重点 | 难点在哪 |
|------|------------|---------|
| **系统创建新品档案** | 档案是后续所有计划与采购的数据地基 | 标签类型涉及**法规符合性**（标签 2 不锈钢接触食品 / 标签 4 纺织需生产许可证 / 标签 6 塑料接触食品需生产商与许可证）；代发品计价方式须统一改为"固定成本价" |
| **协同计划部门发起采购订单** | 衔接需求计划与供应执行的中枢动作 | 要同时消化**交付经理需求计划 + CBG 销量预测 + 实际销量变化 + 仓储盘点 + 供方交期物流**，还要"兼顾物流成本与供方生产平滑节奏做**经济订货**"；季节性/重点款/定制款订货方式各不同 |
| **三单相符**（采购订单-送货单-付款单） | 财务合规与异常发现的关口 | 异常往往跨三方（采购在途、工厂发货、仓储到货），要**自己找问题再同步财务完结** |
| **监控日常库存保交付防滞销** | 岗位的核心目标函数在日维度上的体现 | 依据**每天更新的缺货报表**监控；库存不准、到货未入库要即时沟通；滞销金额大的要推动运营与供开定解法 |
| **日常缺货处理** | 直接对客交付结果负责，最考验应变 | 三种替发路径（可替发 SKU / 供方代发 / 粘胶替发）各有前置条件；还要选对采购单仓库与运费类型 |

### 四、协同网络（PMC 是谁的接口人）

| 协同方 | PMC 找它是为了什么 |
|--------|------------------|
| **交付经理** | 需求计划来源；缺货与异常的协同对象；周会/月会 |
| **供开部** | 新供方与价格、供方档案、**价格变动必须经供开确认**、供方绩效、协商不下的风险升级 |
| **仓储管理部** | 收货准备、到货异常、缺货报表、退换货、代发仓/云仓出入库 |
| **财务部** | 付款、票据、应付账款核对、退款金额同频、三单相符 |
| **质量部** | 供方质量改善、质量异常库存处理、每周二/三质量会 |
| **CBG / 产品市场部** | 销量预测、货品组合编码、清库存流程发起 |
| **客服部 / 分销部** | 大单发货、缺货时客户沟通 |
| **供应商 / 物流货代** | 订单细节、产能交期、发货、赔付、物流方式选择 |
| **数字化组 / IT** | 运费规则需求申请、流程开发（氚云） |

### 五、系统与制度依赖

- **系统栈**：**管家**（主系统，出现频次最高：档案、组合装、库存、采购单、退货单）· **内部系统**（新品采购单、供应商付款账号、采购退款申请单）· **阿里 1688 平台**（配件采购、下单）· **企业微信**（群协同）· **钉钉**（付款申请流程）· **BI 报表**（周例会取数）· 物流查询网站
- **参考制度**（可作为流程工具的索引）：采购部新品管家建档标准及流程 · 采购部货品组合及策略操作标准 · 采购部采购单建立及审核流程标准 · 采购结算常见问题说明 · 采购退款申请单 · 采购异常登记表 · 清库存申请单 · 阿里订单采购申请

### 六、这 34 条怎么变成认证材料 ⭐

> 💡 **LLM 推断 + 方法映射**（依据 [[wiki/任职资格/认证材料准备与答辩实操]] 的六步表达法）

**素材池 → 案例的挑法**：不要 34 条都写。挑**跨部门 + 有取舍 + 结果可验证**的那几条，按手册的"复杂案例六步表达法"讲：最复杂的场景是什么 → 部门要求是什么 → 职位要求是什么 → 我怎么做 → 为什么这么拆 → 结果如何。

**几组高潜力素材**：

| 素材 | 天然带什么要素 |
|------|---------------|
| **三单相符 + 采购在途异常** | 信息收集（多来源核对）、思维能力（拆断点）、诚信担当（暴露账实不符） |
| **日常缺货处理（三条替发路径的选择）** | 思维能力（区分原因）、开放共赢（多渠道分配取舍）、主动性（风险前置） |
| **代发仓/云仓对接 + 退货明细核对** | 团队合作（跨部门）、诚信担当（货款明确） |
| **异常产品耗损成本向供方磋商赔付** | 影响力（推动供方接受）、开放共赢 |
| **清库存 SKU 下架停用 + 防滞销** | 思维（分类判断）、组织意识（推动运营/供开协同） |
| **代发品计价方式统一为固定成本价** | 主动性（发现问题并推机制） |
| **B 端证据链增强（打包视频/司机签收）** | 诚信担当（防平台争议）、思维（从问题到机制） |

**⚠️ 提醒**：本页只给**素材与映射方向**，不给结论。实际举证仍需庞贝自己按 26 项要素的原文口径逐条对照，并核对手册写定的职责边界（见 [[wiki/供应链管理/OTD订单履行与交付流程]] 第六节）。
