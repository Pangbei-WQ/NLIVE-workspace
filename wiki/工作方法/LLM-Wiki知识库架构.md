# LLM-Wiki 知识库架构

> **状态**：unreviewed
> **最后更新**：2026-09-04
> **来源**：[[raw/知识归档/知识档案/LLM-Wiki知识库搭建指南.md]]、[[AGENTS.md]]

## 核心要点

- 本库采用 [Karpathy LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 架构变体：**原始资料区**（`raw/收件箱` 只读 + `raw/知识归档` 分权限）+ **AI 可维护的提炼知识**（`wiki/`）+ **操作契约**（`AGENTS.md`）+ **目录与审计**（`index.md` / `log.md`）。
- 资料走**两段式管线**：`收件箱`（原始累积，只读）→ 转 md 入库 → `知识档案`（原料层）→ 提炼 → `wiki`（知识网络）。
- 定位：让 LLM 当**知识库管理员**，而不是聊天机器人。
- 四大核心原则：**来源至上、诚实标记、级联维护、可逆可审计**。
- 审核状态机：`unreviewed` / `reviewed`（**仅人工可设**）/ `disputed` / `outdated`。
- 🔴 红线：LLM 绝对不得把 `review_status` 设为 `reviewed`。

## 核心机制

### 1. 审核状态机（信任的根基）

| 状态 | 含义 | 谁能设置 |
|------|------|----------|
| `unreviewed` | LLM 生成，未经人工确认 | LLM |
| `reviewed` | 人工已确认 | **仅人工** |
| `disputed` | 发现矛盾，待解决 | LLM 或人工 |
| `outdated` | 已被新资料取代 | LLM（需在 log 说明） |

> ⚠️ 这是"可信"的底线：AI 生成的内容永远不冒充人工审核过。

### 2. 四大流程

- **Inbox（收件箱入库）**：会话启动扫描 `raw/收件箱/` 新文件 → 转 `.md` → 按原标题/内容重命名 → 写入 `raw/知识归档/知识档案/`（frontmatter 记 `original_source`）→ 追加 log。**不动收件箱原文件**。
- **Ingest（摄入提炼）**：读 `raw/知识归档/知识档案/` 的 .md → 识别主题/关联 → 创建/更新 `wiki/` 页面 → **级联更新**相关页面 → 更新 index + 追加 log → 报告。
- **Query（查询）**：先读 `index.md` 定位 → 综合多来源 → 区分三层信息（📌来源事实 / 🔍综合判断 / 💡LLM 推断）→ 先结论后依据、逐条标来源。
- **Write-back（回写）**：有价值问答且无页面覆盖时 → 建 `unreviewed` 页面 → 保留 Q&A 结构 → 标来源 → 更新 index/log。
- **Lint（体检）**：矛盾检查、过时检查、孤儿页面检查、缺失概念检查、来源追溯检查。

### 3. 页面模板要点

YAML frontmatter 含 `date` / `tags` / `review_status` / `sources`；正文含状态块 + 核心要点 + 详细内容 + 相关页面 + 待补充。已在 wiki 页面原文基础上补充更新块时用 `> 📝 更新（unreviewed）`。
