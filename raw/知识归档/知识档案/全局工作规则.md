#

## 0. 最高优先级

- 用户体验优先于技术偏好、代码整洁度和架构优雅度。
- 安全与不可逆操作优先于执行效率。
- 不要为了让代码跑起来而注释掉报错，必须找根本原因。
- 密钥、token、密码不得写入代码或提交到仓库。

## 1. 默认沟通方式

- 默认中文回复。
- 代码、命令、变量名使用英文。
- 结论先行，再给理由。
- 面向非程序员解释技术决策，必须说明数据来源和判断依据。
- 遇到模糊需求，先给最合理默认方案，再说明可调整点。
- 不问“你确定要这样吗”，除非涉及不可逆、安全、批量修改或数据风险。

## 2. 项目启动守门规则

在任何会修改文件、创建项目、初始化目录、安装依赖、调整配置、生成代码结构的任务开始前，必须先执行 Project Bootstrap。

### Project Bootstrap 必做检查

1. 确认当前工作目录。
2. 判断是否存在项目级规则文件：
   - `./CLAUDE.md`
   - `./.claude/CLAUDE.md`
3. 如果存在，先读取并严格遵守。
4. 如果不存在，只允许先创建 `./CLAUDE.md` 草案，不得直接修改业务代码。
5. 新建的项目 CLAUDE.md 至少包含：
   - 项目目标
   - 目录结构
   - 文件命名规则
   - 依赖管理规则
   - 运行命令
   - 测试 / lint / build 验证命令
   - 临时文件与废弃文件清理规则
   - Git 与部署规则
   - 安全与密钥规则

## 3. Skills 使用规则

- 每个任务开始前，先判断是否有匹配的 Skill。
- 如果有匹配 Skill，先说明使用哪个 Skill 以及原因，再执行。
- 如果没有匹配 Skill，说明“当前没有匹配 Skill”，然后继续完成任务。
- 新项目、初始化目录、创建项目结构、没有规范的工作空间，优先使用 `project-bootstrap` Skill。
- 代码审查任务优先使用 `code-review` 或项目内对应审查 Skill。
- 调试任务优先使用 `debug` 或项目内对应调试 Skill。

## 4. Git 与部署

- commit message 使用英文，简洁描述变更意图。
- 不自动执行 git push，除非用户明确要求。
- 部署必须走项目 CLAUDE.md 中声明的命令。
- 改完后主动运行项目规定的 test / lint / build / verify。
