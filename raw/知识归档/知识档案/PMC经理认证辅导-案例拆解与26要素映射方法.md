# PMC 经理认证辅导｜案例拆解与 26 要素映射方法

> **状态**：unreviewed（待人工审核）
> **来源**：[[raw/收件箱/export_1788273799258.md]]（会议语音转写原稿，约 1 小时 46 分钟）
> **会议性质**：**一对一辅导**。被辅导者（PMC / 库存计划岗）先试讲自己的认证案例 → 辅导者逐段点评 → 现场示范"如果是我，我怎么讲" → 逐条带过 26 项要素的讲法。
> ⚠️ 本系列中**含金量最高的一篇**：既是一份认证方法论，也是一份"怎么把日常工作讲成能力证据"的完整示范。
> ⚠️ 转写中人名/术语为语音识别结果，可能不准；本文已尽量改以职能指代。

## 核心要点

- **认证讲的是"理解"，不是"背"。** 辅导者的第一句点评：上来就说"我为什么认证二级"，却**没讲二级的理解是什么**；四个要素只是念了一遍、没谈理解——"这个背是没有意义的，大家没有体感"。
- **正确顺序：先讲"我是干什么的"，再讲等级边界，再讲场景，最后讲映射。** 不要一上来就甩表格——评委（换个部门的领导）根本不知道你的职责范畴。
- **等级边界的讲法是"四个核心特征"**：① 常规业务场景 + 多个业务产品能独立做事 ② 复杂场景需要上级辅导 ③ 独立范围＝常规，辅导范围＝复杂 ④ 目前还没有能力赋能他人 → 三级边界是"精通 + 脱离对部门的依赖"。
- **案例要"深度拆解"再映射**：一个案例 → 拆成流程节点（可能 15 个）→ 每个节点回看对应哪一项能力要素。不要"我好像都做过，评委你看着给分"——**那是没法评分的**。
- **找 3–5 个覆盖广的复杂案例**，不要准备十几个。"**案例越复杂，打分尺度越高**"；正面案例不一定最优，负面案例也可能最优。
- **对上级的依赖度，决定分数落在 P3 还是 P4。** 这是整套映射的胜负手。
- **不要把边界锁死**：认证二级不代表只有二级能力，"我讲六、讲七不行吗？可以"——**溢出边界是加分**。
- **自我检验法**：自己录一遍 15 分钟讲述，回听能不能听懂；听不懂就重做。
- 附：尾段（约 23 分钟）转到了**跨境礼盒/套件的采购入库与开票口径**，与认证无关，但记录了一段真实的系统建模争议（见文末附录）。

## 详细内容

### 1. 被辅导者的试讲内容（库存计划案例）

#### 1.1 为什么不能用单个产品看库存

> 📌 "玩具它是通过组件的形式去组礼盒，然后再去出库售卖。所以我不能以单个产品去看它的销量或者组件库存，我要以**组件视角**去判断整体情况。"

表格搭建口径：
- 以 **Y065（组件）** 为主轴，**Y03 销量**为主
- Y03 **成品总库存 + 组件库存** = 一个整体的"组件成品库存"

#### 1.2 三类需求来源汇总

| 来源 | 特征 | 处理方式 |
|------|------|----------|
| **京东自营** | 每周一提供出货量，但每周推铺货 | 提前把京东订单出货量**导入表内** |
| **分销** | 只提需求，**不是及时性出货** | 在表上**扣除已锁定订单量**，算可用库存 |
| **英式主仓** | 日常出货量 | 结合判断整体库存能否满足销售需求 |

→ 由三者结合判断库存能否满足整体销售需求，再判断**在途提货的时间节点与数量**。

#### 1.3 分销案例（7 月）

- 7 + 8 月总需求约 **9000 多件**；先判断 **7 月**能否满足。
- 数据放进表 → 得出**在库库存储备**，判断**是否低于安全库存储备（15–20 天）**。
- 低于安全库存 → 走**采购代补**（向供应商提货）。
- 但采购代补**并非都有现货**（有的订单在生产中）→ 进一步与供应商沟通"下一批提供时间点是否可以提前"，才能判断这个需求量能不能给。
- 结果：梳理出 7 月需求 **3000 多件**、**8 月 18 日发出**；8 月需求在 8 月底补回后发出。
- **提货记录备注延期原因**（如某工单组件来不及在某时间点发）；等这两个特别组件到货，货才算完全备好。

#### 1.4 试讲者自评的覆盖情况

- 认为该案例覆盖了岗位职责里的 **滚动计划形成、齐套缺料跟踪、物料计划、排产交付、重点订单（分销算重点订单）**。
- **供给信息协同**：需求不能满足时，把客户需求/销量/订单量告诉供应商，请其协调排产。
- 自评偏弱的：**诚信担当**（但认为"如实反馈在库库存、没有放大或缩小需求"也算诚信）、**AI 与自动化**（"目前库存计划里还没用到这一块，主要用 BI 报表数据"）。

### 2. 辅导者点评：这段试讲错在哪

| # | 问题 | 原话要点 |
|---|------|----------|
| 1 | **没讲"二级的理解"** | "你只说四个要素，最后一个讲错了；四个要素的**理解是什么**没谈，只是念经背一遍" |
| 2 | **没前置说明"我是干嘛的"** | "大家知道你做什么吗？评委他哪知道你是干嘛的？听完之后就是懵逼的" |
| 3 | **表格缺"承接关系"** | 表格承接的是哪几个核心职责方向？讲表格的**目的是啥**？ |
| 4 | **没讲"为什么选这个场景"** | 直接讲 to B 分销，"没有来龙没有去脉"；且术语要用他们的语言——"**不能讲分销，在他们的理解里 to b 就 to b**" |
| 5 | **链路跳来跳去** | "对熟悉你工作的人没问题，但对不熟悉的人……表格逻辑其实挺强的，在表格里讲东西很容易讲乱" |
| 6 | **映射推演方式错** | "我说 AI 我没接触过，其他 9 个我都碰过了吧"——**这么推演等于说其他都会**，评委只能狂轰滥炸地追问，**没法评分** |

> 📌 辅导者对"讲得乱"的解法："既然名字一定会问，索性我一次性跟你讲清楚……**在表格里直接加一个流程图**，那很清晰。"

### 3. 辅导者给的正确路径（主线）

```
① 我是干什么的（职责理解）
     ↓ 用一个产品 / 一条流程串起来讲，不要背
② 等级边界（二级 vs 三级 的四个核心特征）
     ↓
③ 业务链路（画得出来，评委才看得懂）
     ↓
④ 场景 / 案例（3–5 个覆盖广的复杂案例）
     ↓
⑤ 案例深度拆解 → 每个流程节点映射到具体要素
```

**关于②二级边界（辅导者的原话拆解）**

- 二级的四个核心特征：
  1. **独立能做事**——在**常规业务场景**、**多个业务产品**上能独立做事；
  2. **复杂业务场景需上级辅导**；
  3. 常规＝自己独立做、不要辅导；复杂＝需要辅导；
  4. **个人能力目前还不足以赋能/带动其他伙伴**，"只能做好自己"。
- 三级边界：**精通所有核心业务产品，已脱离对部门的依赖**，能主导项目。

**关于①职责理解（辅导者的示范）**

> 📌 "你职责一定要理解……你不能现场念，你的核心职责是做什么？要说你对这个职位的理解是什么，因为基于你的理解，你未来在做认证的时候才能讲得更透。"

示范做法（HR 侧）：不做"逐条背职责"，而是**拿一条流程讲清楚**——

- 我为谁服务（业务部门）→ 他的目标 / 现状 / 差距是什么
- 差距分三类：**动力不足**（激励/绩效问题）、**人不缺但人效不够**（人机边界 / AI 应用）、**能力不够**（培训）
- 三类差距 → 对应的组织诊断 / 绩效 / 激励 / 人才盘点 / 任职资格梳理 / 人机边界

> 📌 结论："你的很多场景都可以**串联在一起**做这个事情，就是通过一个流程的概念。"

### 4. 现场示范：两个能力项怎么讲

#### 4.1 信息收集

- **先提炼关键字**：把每个等级的关键字露出来（辅导者原话"我那天有提醒，把每一个等级的关键字给我露出来"）。
- 二级信息收集的标准 = **独立 + 多渠道 + 常规场景 + 复杂问题依赖上级**。
- 正面拆解示范：
  1. **渠道**：我有 SBG 的渠道、PPT 的渠道……够不够全？**超出方案预期 → 加分**；
  2. **独立受理**：所有数据在此，**截图**给你看；
  3. **复杂问题**：分析过程中遇到机制类问题看不懂 → **反馈上级、问上级** → 正好落在二级（依赖上级）。

- **反过来的版本**（中规中矩）：我做到了、独立提供、上级没参与；复杂场景某维度分析我只能停留在"收集完看到表象问题（SMART 层面）"，机制问题看不到 → **同样符合二级**。

> 📌 胜负手："**对上级的依赖度有多高，决定了这个分子可不可以稍微高一点点**"——多依赖 = P3 区间，少依赖 = P4 区间；如果复杂问题都能独立分析并给出正确结论 → **超出范畴，直接高分**。
> 📌 表达时把**四个维度**融进去：多渠道 / 独立 / 常规多场景 / 复杂场景；不要刻意念，要"顺其自然地表达"。

#### 4.2 思维能力

- 核心定义（辅导者口径）：**把一句话拆成可视化/好理解的东西，算思维能力**。
- 例："常规组织问题" → 拆成 **目标 / 流程 / 职责 / 能力 / 人员 / 协同因素**，找到明显问题本质。
- 思维路径三步：① 拆解关键要求 ② 拿案例去预测映射 ③ 解释为什么这个案例满足要求 + **把边界讲清楚**。
- **案例的复杂程度决定打分尺度**：简单案例（如一般招聘问题）分数上限低。
- **招聘案例的示范**（海外 CPG 运营招聘）：
  - 不要只看需求本身，要抓**需求背后的本质**：是不是我们某块能力有缺口？缺口决定**人才画像**。
  - 还要横向对标：**市面上顶流跨境电商公司这个岗位的画像长什么样** → 反馈给业务主管。
  - 招聘的闭环**不止于入职**：要等入职后 3 个月、转正甚至一年，验证能力是否真的补了缺口。
  - **猎聘思维 vs 常规招聘思维**的区别："很多公司招了人入职就拜拜再见，好的公司做员工在职生命周期数据跟踪"。

### 5. 辅导者的亲身案例：珠宝公司 214 备货（复杂案例示范）

这是本场最完整的一个"复杂案例怎么讲"的样板，值得单独存档。

**背景**
- 珠宝公司，**2/14 是旺季**；备货逻辑是 **5–7 天为一个备货周期、小批量滚动、疯狂周转**，不做大批量备货。
- 矛盾点：**老品很少、新品贼多**（女性首饰，季节性强、阶段性差）。

**流程与尴尬节点**
1. 新款上市 → 只能**试卖 3–5 件**（从 1688 走）→ 卖得不错 → 找供应商下大货；
2. 大货**第一批也只有 100 件**，仍是小批量滚动；
3. 结果：供应链天天从早干到晚补小单；"3 件到库，一到库发现预售卖完了，大单马上出，出完就尴尬——出货要 3 天，但库存没有"。

**关键约束**
- **老供应商不愿接小批量**（"你想给他货，我员工都不够"）→ **1688 可以** → 解法是**两条路都走、把量拆开**；
- **银价实时定价**：今天 10 块、明天 15 块，**以报价单发出的微信时间戳为准**——下单早/晚一个月，可能差 **50 万**；
- 渠道：唯品会一仓 + 天猫一仓，**同一批货条码不同要分开发**，徒增难度。

**解法演进（一步步拆）**
1. 找老供应商要**同款清单**，据此备货；
2. 小批量与大批量**分开走**（大货给小批量接不了的头部供应商，小批量给 1688）；
3. **兜底模式**：以市场单价为基准，"一个月内波动不超过 10%，我分你 10%"；
4. 改为**半成品（手镯化成品）备货**，降低银价与工期风险。

**反思与外部对标**
- 本该"倒逼前端给销售计划"，但"人家不接受" → 只能在**内部供应链做调整**；
- 平台供货模式的残酷性（唯品会 / 京东同理）：**平台向你调库存，备货跟不上就被踢掉**。举例波司登羽绒服"一天出 5 万件，就变成空半指标了"——**平台为大、商家是小**；
- 学习方式：去对方工厂看珠宝生产工序，才理解**实时定价**的由来——手工作坊、没有压系统、报价单以微信发出时间结算。

**辅导者抽象出的"六步表达法"**（可直接套用到任何复杂案例）

| 步骤 | 内容 |
|:--:|------|
| 1 | 业务里**最复杂的场景**是什么？先把来龙去脉讲清楚 |
| 2 | **部门 / 业务的要求**是什么？ |
| 3 | **你自己职位的要求**是什么？ |
| 4 | 我**怎么做**？把它拆成一二三四步 |
| 5 | **为什么这么拆**？过程是什么？ |
| 6 | **结果**如何？有没有达到预期？部门认不认可？ |

> 📌 结论："**一件复杂事物的拆解能力**，会成为你未来核心表达的东西，这个才是证明你的能力的地方。"

### 6. 逐条 26 要素的讲法要点（辅导者一条条带过）

| 要素（场景） | 二级标准要点 | 加分/提醒 |
|--------------|--------------|-----------|
| **看板预警与异常确认** | 能独立使用看板、预警 skill，完成常规计划，识别主要变更，确认排程冲突，提交需人工确认事项 | 若"我有能力自己提看板需求、上级把关后提给 IT 实现"→ **加分** |
| **库存结构与周报复盘** | 独立完成常规库存结构、观察订单交付周报/成本、识别主要偏差、形成改善建议 | 前提是**懂底层逻辑**：呆滞多久算呆滞、周转怎么看、头/腰/尾部产品差异、僵尸库存 3 年以上动销、库存 = 在途 + 在库 + 计划下单、年度库存、库存准确率（SPU vs SKU） |
| **模板沉淀** | 能独立沉淀常规计划模板（PMC 的表格）、排程清单、全量运行、变更记录 | "表格不讲逻辑，逻辑是前层/头层/后层，能讲清楚就行" |
| **跨部门对接对齐** | 独立完成常规跨部门对接（公开/采购/制造/仓储/质量/地区/包装/交付），达成一致的排程、物料状态、开始节点 | 分两类：**常规同频＝兜底分**；**问题同频＝加分**。"不要局限于常规情况，再找有没有特殊案例" |
| **问题复盘与风控** | 问题发生 → 我去解决 = 应变能力 | 若进一步**沉淀成 SOP / 预警 / 预控** → "那可能就是**三级能力**"——做二望三 |
| **入货齐套 / 补货节奏** | 独立完成常规进货节奏、产品属性、渠道差异、齐套短交触发、交期平稳分析 | 讲清"入库异常**多少是你发现的、多少是别人发现的**"；超出职责范畴发现 = 创造额外价值 |
| **履约 / 推进** | 围绕需求计划，完成常规 PO 下单、供应商交期、物料齐套、状态更新 | **分三段识别**：① 前面干的活 ② 借助 AI 干的活 ③ 推进的部分 |

> 📌 通用提醒："**不要把边界给自己锁死**——如果我有能力自己提需求、自己输出，那就在边界之上，是加分。"
> 📌 关于 PMC 的核心指标：不能说"不缺货"（这个行业做不到），应该说"**缺货率低于多少 / 重点品不缺货 / 高速转品不缺货 / 常规品控制在多少以内**"——**不要把话说死，也不要说太满**。

### 7. 操作层面的明确建议

- **案例数量**：**3–5 个覆盖更广的案例**。"我建议十几个、十个就太多了""三到五千字你讲不了真的讲不了"。
- **讲述时长**：正常 20–30 分钟；四到五个案例，每个约 **6 分钟**。
- **呈现方式**：建议 **PPT**（映射关系直观；表格讲流程慢）。
- **准备节奏**：先找案例 → 辅导者**帮你拆一个 MVP** 示范 → 你自己再拆。**预认证的伙伴才有辅导**，没参与认证的不出手帮。
- **自我检验**：自己录一遍 15 分钟，回听能不能听懂；"自己听不懂就重做"。
- **正反案例**：正面案例不一定最优，**负面案例也可能最优**。
- **3–5 个案例仍覆盖不全时**："先找出来，覆盖不了只能覆盖三个（要素）就先这样"。
