# LLM Wiki 知识库搭建指南（raw + wiki + AGENTS.md 复现手册）

> **状态**：unreviewed（LLM 整理，未经人工审核）
> **最后更新**：2026-08-19
> **用途**：让任何人（或任何 AI）照此重建与本 vault 同构的"LLM 维护型知识库"。本指南是对本 vault `AGENTS.md` 的通俗化 + 可复制化说明。

---

## 一、这套结构解决什么问题（先懂原理）

普通 Obsidian 库的问题：
- **只存不整**：笔记越堆越多，只见收藏、不见消化；
- **来源不可追溯**：AI 说了一句话，没人知道它从哪来，业务/个人都不敢信；
- **AI 不敢放手操作**：没有契约，AI 分不清哪些能改、哪些不能改，容易越权或毁数据。

LLM Wiki 架构的回答（灵感来自 [Karpathy LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)）：

> **把知识库分成"不可变的原始资料"和"AI 可维护的提炼知识"两层，用一份契约（AGENTS.md）规定 AI 的行为边界，再用 index + log 做目录和审计。** 让 LLM 当"知识库管理员"，而不是"聊天机器人"。

四个核心设计决策：

| 决策 | 原因 |
|------|------|
| `raw/` 只读不可变 | 原始资料是"证据"，AI 绝不能篡改，否则无法溯源 |
| `wiki/` 由 LLM 维护 | 提炼、编织、整合是 AI 最能增值的地方 |
| `AGENTS.md` 契约 | 把 AI 的权限/流程写死，它才知道边界在哪、怎么干活 |
| `index.md` + `log.md` | 目录可导航、操作可审计，知识库"可验证" |

## 二、目录结构与权限

```
vault-root/
├── AGENTS.md              # 📜 LLM 操作契约（人工维护，改需确认）
├── raw/                   # 📥 原始资料（不可变，LLM 只读）
│   ├── 文档/              #   文档、笔记、读书笔记、日记
│   └── 网页剪藏/          #   浏览器剪藏等
├── wiki/                  # 📚 LLM 维护的知识库（AI 全权维护）
│   ├── index.md           #   知识目录（每次 Ingest 后更新）
│   ├── log.md             #   操作日志（append-only）
│   └── [领域]/[页面].md   #   知识页面，按领域组织
└── *.md                   # 根目录散落笔记（人工撰写）
```

| 目录 | 读取 | 写入 | 修改 | 删除 | 说明 |
|------|:----:|:----:|:----:|:----:|------|
| `raw/` | ✅ | ❌ | ❌ | ❌ | 只读，原始资料不可变 |
| `wiki/` | ✅ | ✅ | ✅ | ✅ | LLM 全权维护，index/log 每次操作必更新 |
| `raw/文档/Daily/` | ✅ | ❌ | ❌ | ❌ | 日记是人工私人空间 |
| `AGENTS.md` | ✅ | ⚠️ | ⚠️ | ❌ | 修改前需人工确认 |

## 三、核心机制

### 1. 审核状态机（信任的根基）

每个 wiki 页面的 YAML frontmatter 里有 `review_status`：

| 状态 | 含义 | 谁能设置 |
|------|------|----------|
| `unreviewed` | LLM 生成，未经人工确认 | LLM |
| `reviewed` | 人工已确认 | **仅人工** |
| `disputed` | 发现矛盾，待解决 | LLM 或人工 |
| `outdated` | 已被新资料取代 | LLM（需在 log 说明） |

> ⚠️ **红线**：LLM 绝对不得把 `review_status` 设为 `reviewed`。这是"可信"的底线——AI 生成的内容永远不冒充人工审核过。

### 2. Ingest 流程（资料进来）

1. 读 `raw/` 中的新文件 → 识别主题/概念/关联点 → 向用户报告；
2. 创建/更新 `wiki/[领域]/[页面].md`（遵循页面模板）；
3. **级联更新**：遍历相关页面补链；改已审核页面时只追加"更新块"不改原文；
4. 更新 `wiki/index.md`（目录 + 统计）+ 追加 `wiki/log.md`；
5. 向用户报告 Ingest 结果。

### 3. Query 流程（知识出去）

1. 先读 `index.md` 定位 → 打开相关页面 → 必要时追溯 `raw/`；
2. 区分三层信息：📌来源事实（可直接引用）/ 🔍综合判断（标注推断）/ 💡LLM 推断（标注未验证）；
3. 先给结论，再列依据，每条标注来源 + 审核状态。

### 4. Lint 健康检查（定期维护）

- 矛盾检查（disputed）、过时检查（outdated）、孤儿页面检查、缺失概念检查、来源追溯检查。

## 四、给 AI 的一键初始化 Prompt（复制即用）

> 把下面这段发给任意一个有能力读写文件的 AI（Claude 等），在**空 vault** 里就能搭出同款结构。它已经内置了本指南的全部要点。

```text
你是一位知识库管理员。请把当前目录改造成一个"LLM 维护型知识库"，遵循 Karpathy LLM Wiki 架构。

## 第一步：创建结构
1. 创建 `raw/` 目录（原始资料，不可变）和 `wiki/` 目录（LLM 维护的知识库）。
2. 在 `wiki/` 下创建 `index.md`（知识目录）和 `log.md`（操作日志，append-only）。
3. 创建根目录 `AGENTS.md`（LLM 操作契约），内容必须包含：
   - 角色定义：LLM 是知识库管理员，负责把 raw/ 消化提炼进 wiki/，响应用户查询并引用来源，定期健康检查。
   - 四条核心原则：来源至上（所有论断可追溯）、诚实标记（推断不冒充已审核）、级联维护（新资料入库时更新所有受影响页面）、可逆可审计（每次操作记 log）。
   - 目录权限表：raw/ 只读不可变；wiki/ LLM 全权维护；raw/文档/Daily/ 只读；AGENTS.md 改前需人工确认。
   - 审核状态机：unreviewed / reviewed（仅人工可设）/ disputed / outdated，并写明"LLM 不得把 review_status 设为 reviewed"。
   - Ingest 流程、Query 流程、Write-back 流程、Lint 健康检查流程。
   - 页面模板（YAML frontmatter 含 date/tags/review_status/sources）。
4. 如果目录里已有笔记，把它们归类移入 `raw/` 对应子目录（如 文档/、网页剪藏/）。

## 第二步：首次摄入
把 raw/ 里的现有资料消化、提炼，为每个主题创建 wiki 页面，状态设为 `unreviewed`。领域标签示例：#供应链 #AI工具 #任职资格 #工作方法。页面用 wiki-link（[[页面名]]）互相连接。

## 第三步：收尾
1. 更新 `wiki/index.md`：按领域索引所有页面 + 顶部"最近更新" + 统计表（Wiki 页面数 / 读书笔记 / 学习小组 / 知识整合 / 其他 / Raw 源文件 / 覆盖领域 / 未审核页面）。
2. 在 `wiki/log.md` 顶部追加一条 init 记录，格式：`## [YYYY-MM-DD HH:MM] init | 描述`。
3. 向我报告：创建了哪些目录/文件、把哪些现有笔记归入 raw/、新建了哪些 wiki 页面、有哪些待补充。

## 约束
- 所有 wiki 页面 `review_status` 必须为 `unreviewed`，绝不设为 `reviewed`。
- 不修改 raw/ 中的任何原始内容。
- 全程使用相对路径。
```

## 五、日常维护速查表

| 想做 | 怎么做 |
|------|--------|
| 丢一份新资料进来 | 放 `raw/` → 让 LLM 执行 Ingest |
| 问知识库一个问题 | 让 LLM 执行 Query（先结论后依据，标来源） |
| 让 LLM 记住一次有价值的问答 | 让 LLM 执行 Write-back（3 来源以上综合 → 建页） |
| 体检知识库 | 让 LLM 执行 Lint（矛盾/过时/孤儿/缺失概念） |
| 审核一个页面 | 人工把 `review_status` 从 `unreviewed` 改为 `reviewed` |
| 改结构/规则 | 改 `AGENTS.md` 需人工确认，改后记入 `wiki/log.md` |
| 想看全貌 | 打开 `wiki/index.md`；Obsidian 图谱看页面间连接 |

## 六、本指南 vs AGENTS.md 的关系

- **AGENTS.md** = 本 vault 的正式契约（`reviewed`，人工维护），定义"AI 在本库必须怎么干活"。
- **本指南** = 契约的通俗化 + 可复制化版本（`unreviewed`），用于"教别人 / 教新 AI 重建这套结构"。
- 两者内容同源；若 AGENTS.md 更新，本指南需同步，反之亦然。
